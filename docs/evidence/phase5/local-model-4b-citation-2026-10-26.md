## 环境与方法

全部运行在 Linux 测试服务器。模型为 Qwen3-4B-Q4_K_M，本地 GGUF SHA-256 `7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5`，OpenAI 兼容 API 仅绑定 Docker 桥接地址。使用实际论文 PDF，通过 PyMuPDF 从物理页抽取 344–660 字符的相关段落，再加入另一个物理页的干扰段落。测试调用产品的 `buildSystemPrompt` 和 `verifyPdfAnswer`，以温度 0 请求本地 API。每次原始回答都含模型 `<think>` 段，产品校验器移除后才将正文显示。

每份证据又问一次论文中不存在的作者诺贝尔奖日期。模型四次都生成“无法从 PDF 核实”，产品显示四次统一拒答；无编造页码。原始合成 QA 脚本、段落和输出保留在服务器私有目录 `/home/gavin/.readest-scholar-private/phase5-qa-4b`，证据 JSON SHA-256 `e1b14687c58648d157b1c11a32da00c5f30793d6463a3f68a19b30410e885650`、结果 JSON SHA-256 `dc7aac963b95cc4dbc34ca8e30efc1f3a16c70297b730a52782367070139f6d6`。段落不放入公开仓库。

这次是产品提示词和校验器加真实 API 的抽样；[此前原生阅读器回放](native-paper-answer-qa-2026-10-23.md)验证了 PDF 索引、来源卡片跳页、错误页码阻断与 UI 拒答，但使用较小模型。两组证据合并覆盖功能路径，不构成大规模语义蕴含基准。非数字断言仍需读者查看来源。账户索引隔离与凭据保存另见 Phase 5 的检索和凭据记录。
