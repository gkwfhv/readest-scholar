# Phase 1：升级后 Web→macOS 阅读进度复验（2026-10-20）

范围：已授权的单机 Linux staging、SSH 回环隧道、独立标识的未签名 macOS 测试包。仅使用仓库自带的两页 `sample-paper.pdf` 和 staging 合成账户；没有使用真实用户资料或正式签名渠道。Web 运行镜像仍是 [固定摘要升级记录](staging-web-rollout-2026-10-20.md)中的 Scholar 镜像。

## 隔离与前置条件

- Web 从 `http://localhost:3000` 进入隧道，后端分别通过回环 `127.0.0.1:3130/8130/9130` 访问。`src/middleware.ts` 允许 `http://localhost:3000` 的 API 跨域请求；`http://127.0.0.1:3000` 没有该授权，预检响应缺少 `Access-Control-Allow-Origin`，所以不能把后者的翻页显示当成已上传进度。
- staging 原有阅读书籍属于另一合成账户。本次使用的私有恢复探针账户起初没有书籍；两者的账号标识哈希核对不同。先在 Web 为探针账户导入仓库样例 PDF，并点“上传到云端”。数据库只读查询确认该账户的书籍 `uploaded_at=2026-10-20 14:47:30.85 UTC`。没有把不同账户的书籍记录混作同步证据。
- 桌面测试包使用 staging 的公开回环 API 配置构建，保留 `com.readest.scholar.silo-test` 独立标识。测试前它在原合成账户的同一本 PDF 上有第 2/2 页的本地位置；切换到探针账户后才打开本次 Web 写入的位置。切换账户保留了本地合成书库，并把其中另一部公版测试书自动同步到探针账户；该副作用仅发生在合成 staging，不能推广为跨账户隔离测试通过。

## 实际观察

1. Web 在探针账户打开 PDF，第 1/2 页显示 `TITLE OF THE PAPER`；翻到第 2/2 页后，`public.book_configs` 中该账户的新记录为 `progress="[2,2]"`、`location=epubcfi(/6/4)`、`updated_at=2026-10-20 14:47:56.106 UTC`。
2. Web 再翻回第 1/2 页。服务端记录更新为 `progress="[1,2]"`、`location=epubcfi(/6/2)`、`updated_at=2026-10-20 14:48:41.439 UTC`。[Web 页码截图](web-source-page1-2026-10-20.jpg)保留了第 1/2 页画面。
3. 桌面测试包登录**同一个探针账户**，打开本地原先停在第 2/2 页的同一 PDF。原生界面出现“阅读进度已同步”，正文回到 `TITLE OF THE PAPER`，页码为 `1 / 2`。随后服务端仍为 `"[1,2]"`，位置仍为 `epubcfi(/6/2)`；没有被旧的本地第 2 页覆盖。[桌面截图](web-to-desktop-page1-2026-10-20.jpg)同时显示同步后的页码，以及同一侧栏底部的目录、笔记、书签、大脑聊天四入口；脑图标高亮块完整处于约 480 物理像素的侧栏边界内。

这验证了**升级后 Scholar Web 写入 → staging 后端持久化 → 独立 macOS 测试包采用新位置**的路径。此前的[桌面→后端新进度证据](staging-web-rollout-2026-10-20.md)覆盖反方向。这里只验证同一台测试 Mac、一个合成账户和一个两页 PDF；离线冲突、多用户、移动端及正式签名安装包尚未覆盖。

本次为登录测试临时转移的合成账户文件和公开构建配置文件均已从本机 `/private/tmp` 删除；浏览器临时标签页已关闭，内存中的凭据引用已清空。仓库只保存不含账户标识和秘密值的记录与截图。
