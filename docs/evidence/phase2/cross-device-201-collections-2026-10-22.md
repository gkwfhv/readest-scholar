# Phase 2: 201-document Web ↔ desktop collection and metadata round trip (2026-10-22)

Scope: only synthetic PDFs and a test account on the SSH-tunnel-only staging backend. The Web side ran candidate source `8c384ca71`; the native side used an existing, independent macOS `Readest Scholar Update Smoke` test bundle (`io.github.gkwfhv.readestscholar.updatesmoke`, version `0.12.17`) with an empty local library before sign-in. The test bundle predates the new three-pane layout and DOI editor, so this proves cross-device data compatibility, not updated native visual acceptance. No GitHub/GHCR push or production data was involved.

## Round trip

1. In the Web three-pane library, after 201 PDFs had been imported, Paper 101 was placed into `Phase2 UI Review` and given DOI `10.5555/readest-scholar.phase2.101` plus tags `Phase2 UI QA` and `Cross-device`. The authenticated server `books` row matched the group and tags. [Initial Web view](phase2-three-pane-201-group.jpg).
2. The separate desktop bundle signed into the same synthetic account and displayed `201` books. Its Paper 101 details showed both tags; its grouping dialog offered `Phase2 UI Review` with removal enabled, confirming the Web-created membership reached the desktop. The native library was initially blank while importing 201 records, then rendered searchable cards; this was observed rather than counted as a load-performance pass.
3. On desktop, Paper 101 was moved into the new `Phase2 Desktop Review` group. An authenticated server read then showed `group_name=Phase2 Desktop Review`. After Web reload, the three-pane navigation showed `Phase2 Desktop Review (1)` and `Phase2 UI Review (0)`, with Paper 101 in the new group.
4. In the older desktop metadata editor, the two existing tags were retained and `Desktop QA` was appended. The server row showed all three tags and retained the original DOI in `books.metadata`; the older client did not erase the DOI field it cannot edit. After Web reload, the right pane displayed all three tags and the unchanged DOI. [Final Web view](phase2-web-desktop-return.jpg) and [native accessibility capture](phase2-desktop-metadata-ax.txt).
5. The candidate download API still returned 201/201 URLs with 3/3 PDF SHA-256 matches; the second synthetic account received 0 URLs. A fresh second-account read returned 0 rows in each of `books`, `files`, `scholar_documents`, `scholar_document_books` and `scholar_document_files`. This edit exercise did not alter those authorization rules.

The native screenshot capture intermittently returned a scaled window preview, so no native bitmap was used as layout evidence. The accessibility capture, Web screenshot and authenticated server reads independently confirm the data round trip. The updated three-pane native candidate still needs its own build and visual test before Phase 2 can be accepted. The Web candidate was rolled back from staging after a separate [upgrade/rollback exercise](staging-image-upgrade-rollback-2026-10-22.md); the isolated candidate on port 3132 remains available for QA.
