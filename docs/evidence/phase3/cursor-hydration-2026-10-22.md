# Phase 3：副本游标加载与保存竞态（2026-10-22）

**状态：此项定向验收通过；Phase 3 整体仍在开发。** 代码、测试和提交均在 Linux 测试服务器，未推送 GitHub/GHCR。

## 缺陷与修复

`createSettingsCursorStore` 初始化时异步读取本地设置。若本会话先确认了新游标，再收到旧的初始化结果，原实现会把新值倒退；保存时还会用内存快照覆盖另一窗口在初次加载后写入的其他类型游标。现在加载和保存时按 HLC 取较大值，且旧的 `set` 不会使内存游标倒退。

新增两个先红后绿的回归场景：迟到的初始化读取不得覆盖本会话新值；另一窗口已保存的类型游标不得被本次保存抹掉。相关游标、管理器和本地应用测试 78/78 通过；`pnpm lint` 的 TypeScript/Biome lint 及两份改动文件的 Biome 格式检查通过。`git diff --check` 通过。

## 边界

这只修复本地异步加载与顺序发生的跨窗口保存；当前设置文件的读—改—写不是事务，两个窗口同时保存仍需在新游标存储中验证。旧游标也未按账户隔离。服务端按行 HLC 拉取且 1000 行截断的问题，及长期离线清单/复活冲突，仍按 [ADR 0004](../../adr/0004-replica-change-cursor.md)继续处理。上一提交 `c79bacbf8` 的应用全量测试为 13,868 通过、16 跳过；本次小改动未重跑整套 13 分钟用例，Phase 3 整体不得据此验收。
