# Phase 3：不可变文件的额度预留

范围：Linux 测试服务器本地分支和隔离数据库 `scholar_note_restore_probe`；未修改现有 staging 数据库，未向 GitHub/GHCR 推送。

`042_scholar_file_quota_reservations.sql` 以账户锁序列化预留操作。计算占用时同时计入未删除的旧 `files` 字节、待上传版本和已验证版本；旧文件对象依然存在，因此不会把旧记录当成可抵扣的空间。预留操作绑定文件、操作 ID、SHA-256、大小和从有效会话计算的额度。重复操作返回原版本；过期预留释放额度且不能再完成上传。普通登录角色不能直接执行预留或完成函数。

隔离库验收：`test-scholar-file-quota.sql` 覆盖重复预留、额度拒绝、过期释放、过期完成拒绝和角色权限；更新后的 `test-scholar-file-versions.sql` 覆盖版本 CAS、哈希核验、跨账户隔离及恢复。两项均在事务中运行并回滚探针行，退出码 0。

仍需：可信 API 从已验证的用户令牌提取额度，发放只创建的签名 URL，实际上传后读取对象并校验 SHA-256，再完成版本；客户端切换、旧版兼容、对象清理及真实故障注入。此项只是数据库基础，Phase 3 未验收。
