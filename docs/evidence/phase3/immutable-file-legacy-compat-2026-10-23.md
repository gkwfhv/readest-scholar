# Phase 3：文件版本与旧下载/上传接口的兼容验收

范围：Linux 测试服务器本地分支、回环候选 Web `127.0.0.1:3141`、合成 staging。候选镜像仅在服务器本地，ID `sha256:a1b5969e41a14cf4daa0fde048e9dd2e78e22d23dec537499da706a186700e1e`。正式 staging Web `127.0.0.1:3130` 仍为原镜像；未向 GitHub/GHCR 推送。

旧 `/api/storage/download` 对 Scholar 正文文件保留原 `fileKey` 请求形式，但有活动版本头时签发该头所指向的已验证对象 URL；指针存在而目标版本未就绪时拒绝回退旧对象。无版本头或未安装 Scholar schema 的既有服务仍走原路径。批量封面下载不额外查询 Scholar 版本表。旧 `/api/storage/upload` 遇到已有活动头的正文文件返回 409，避免旧客户端覆写别名后误以为其修改成为当前版本。

单测先复现“旧上传签出覆盖 URL”“旧下载返回旧键”“封面无谓查询”的失败，再覆盖活动头、缺失已验证目标、未版本化文件、缺少 Scholar schema 和 201 项批量下载回归。定向测试及 TypeScript/Biome 通过；服务器 standalone Web 构建通过。

真实合成链路：创建临时书籍，旧 API 上传原始字节并通过旧下载请求读回；以同一 `files.id` 调用新版本准备、只创建 PUT、完成后，**相同的旧下载请求**读回新版本字节；再走旧上传 API 得到 HTTP 409。临时书籍、文件、版本对象和数据库记录已清理。

这项尚未部署到正式 staging Web。此前已签发的旧 PUT URL 在有效期内仍可能写旧对象，但新版下载别名不会把该对象当作活动版本。旧客户端会看到明确的上传失败；实际客户端界面提示、持久离线队列、配额统计、文件删除生命周期和双设备混用仍需验收。ADR 0005 记录后续过渡协议。
