# Phase 3：活动与历史文件版本下载

范围：服务器本地分支、回环候选 Web `127.0.0.1:3140` 和合成 staging。正式 staging Web 仍为原镜像；未向 GitHub/GHCR 推送。

`GET /api/scholar/files/download` 可按 `fileId` 返回本账户活动版本，或按 `fileId` 与 `versionId` 返回本账户已验证历史版本的 5 分钟签名下载 URL、SHA-256 和大小。未完成版本与其他账户的版本不签发 URL。三个定向测试从接口不存在的失败状态开始，覆盖活动版本、未就绪或跨账户版本、未认证请求；修复后通过。TypeScript/Biome、服务器 standalone Web 构建通过，新路由进入产物。

在服务器本地 Docker 候选镜像 `sha256:ebe4cc400402760857377b12d43bfd0dc43407290b6d822c0e8b10047148b5bd` 上，用合成账户上传两个内容不同的版本：两个只创建 PUT 都成功且重复 PUT 被拒绝；首次完成为 200，第二次使用过期空头快照完成为 409。此时活动下载仍是第一个版本，指定历史版本下载返回第二个版本，逐字节和 SHA-256 都匹配。将第二版本恢复为活动版本后，活动下载返回第二份字节；另一合成账户指定该版本下载返回 404。临时对象与记录已清理。

客户端尚未切换到版本下载路径；通用旧下载接口仍读取原 `files.file_key`。缓存策略、完整镜像设置、文件删除生命周期与双设备故障验收仍是 Phase 3 门槛。
