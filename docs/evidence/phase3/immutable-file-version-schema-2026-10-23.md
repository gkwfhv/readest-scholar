# Phase 3：不可变文件版本数据库基础

日期：2026-10-23。服务器本地分支、合成 staging 快照恢复的隔离数据库 `scholar_note_restore_probe`。**尚未部署到 staging，也尚未改变现有上传 API。**

## 变更

迁移 `041_scholar_file_versions.sql` 为已关联到 Scholar 文献的 `files` 行增设不可变版本表与活动版本指针。准备操作使用账户、文件与操作 UUID 幂等定位，并给每个版本分配账户前缀下独立对象键；同一操作 UUID 携带不同哈希或大小会拒绝。可信服务端验证对象字节后才能调用完成操作。完成操作在文件行锁下以预期活动版本作比较交换：先完成者激活，落败者仍保留为已验证版本。已验证旧版可由账户持有者在快照未变化时恢复。

直接表写入只授予服务角色；登录账户可只读自己的版本及活动指针、调用准备与恢复。完成函数只授予服务角色，防止客户端把未上传的内容自行标记为已验证。

## 验证

- SQL 探针在迁移前因函数不存在而失败；隔离库应用迁移后，整套回滚事务通过。覆盖同操作重试、独立对象键、错误哈希拒绝、三个等长版本中两个争用时落败版本留存、旧版恢复、过期恢复拒绝及跨账户准备拒绝。
- 数据库权限直接检查：`authenticated` 对版本表 INSERT 为 false、SELECT 为 true，对完成函数 EXECUTE 为 false；`service_role` 对完成函数 EXECUTE 为 true。
- 探针以 ROLLBACK 收尾，隔离库不保留合成版本行。原 staging Web、数据库和对象存储未改变，没有 GitHub/GHCR 推送。
