# Phase 3：书籍正文的不可变版本客户端接入

服务器分支 `feat/scholar-offline-metadata` 上，Scholar Web/独立测试包的书籍上传现在先登记文件 ID，再用持久队列中的操作 ID 和入队时已知的版本基线执行条件上传。账户 ID 从当前访问令牌提取并与任务绑定；旧账户任务不会在新账户下发送。服务端 CAS 拒绝时不标记书籍为已上传，且不自动重复同一冲突操作。队列正在退出时的新处理请求也能再次唤醒队列。

下载先查询活动头，再请求指定的不可变版本。字节先写临时路径，检查长度与 SHA-256，复制到书库后才记录按账户和云路径隔离的版本基线；失败时清理临时文件，保留原书籍。普通上游构建继续使用原传输分支。

测试先红后绿：基线存储、书籍上传/下载、队列 CAS 冲突/账户隔离/唤醒、传输持久化均有回归。定向 32 项通过；全量 Vitest 13,976 通过、16 跳过（退出码 0）；TypeScript 和 Biome 通过。服务器容器 Web standalone 构建通过，本地候选镜像 `sha256:a9e3d517f71a070d041484d07570a548964ecdf4b0c0cf982df991b6807bb8a6` 在 `127.0.0.1:3145` 返回首页 200、匿名文件状态接口 403。合成账户通过真实 HTTP 验证文件登记、条件上传、活动状态、指定版本下载的长度/哈希/字节、旧下载别名与配额，随后清理数据库行和对象。正式 staging Web 仍为旧镜像；没有向 GitHub 或 GHCR 推送。

未验收：当前队列只持久保存操作 ID 与版本基线，未在入队时保存不可变的本地正文快照；本地文件在等待期间改变会使重试无法复用同一操作。新账户切换后的队列重建、二进制冲突处理界面、按需缓存/完整镜像、双设备原生客户端故障注入仍需完成。因此 Phase 3 未通过。
