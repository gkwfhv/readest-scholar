# Phase 3：笔记冲突历史与原子比较（2026-10-23）

**范围：服务器本地开发、隔离数据库与仅回环开放的合成 staging。Phase 3 整体尚未验收。没有向 GitHub/GHCR 上传。**

## 发现与实现

- 原 `/api/sync` 用删除时钟和编辑时钟的独立比较判断笔记胜负；较旧的删除可能覆盖较新的编辑，同时间戳的编辑也可能复活墓碑。服务端预先跳过落败写入，既不能留存冲突版本，也挡不住两个设备在读取后并发写入。
- 迁移 037 增加按账户隔离的 `book_note_conflict_versions` 和 `BEFORE UPDATE` 行锁比较：按 `max(updated_at, deleted_at)` 判定，同时间戳删除优先；被替换的旧版本和落败的新版本都以内容哈希去重归档。历史只允许所属账户读取，已登录客户端无直接写入权。
- 同步 API 对笔记统一执行数据库 upsert，并重读最终权威行返回。原有新笔记插入时间戳仍用于旧客户端的增量拉取。迁移 038 让内容相同而仅创建/更新时间不同的重试成为无副作用操作，避免首次插入响应丢失后产生虚假冲突。
