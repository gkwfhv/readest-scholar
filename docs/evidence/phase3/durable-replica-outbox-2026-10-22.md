# Phase 3：副本元数据的持久离线队列（2026-10-22）

**状态：实现、定向测试、全量回归和服务器 Web 候选产物检查通过；运行时故障验收进行中，Phase 3 整体未通过。** 开发与构建均在 Linux 测试服务器进行，未推送 GitHub 或 GHCR。

## 实现范围

- 普通副本行在进入内存发送队列前，先按账户、类型和副本 ID 写入本地持久日志；存储失败不会被误报为已排队。书架仍使用它已有的独立日志。
- 启动时恢复待发送行，服务端确认后才删除。断网、服务端短时故障或进程退出后，待处理行保留；网络或服务端失败的发送以 5 秒起、最高 60 秒的间隔重试，不依赖浏览器恰好发出 online 事件。非书架副本操作时间与本机相差超过 30 秒时保留在队列，暂不发送：现有服务端同时把行时间戳用作文件清单/复活令牌冲突顺序和拉取游标，重写它会带来静默覆盖风险。
- 一个账户的待处理行不会与另一账户相同副本 ID 的行合并，发送前再次核对当前登录账户和同步分类。用户关闭凭据同步后，发送前再次按适配器的加密字段名单过滤已经入队的凭据，避免先入队后关闭时仍上传密文。
- 发送过程中本窗口或另一窗口写入了较新版本时，旧请求的确认不能清除它；当前窗口重新排队较新版本。损坏的日志条目会被跳过且保留原始内容，避免把无法解析的数据当作成功发送。

## 明确未覆盖

- 书籍、阅读进度、笔记、批注等旧同步通道尚未纳入这份普通副本队列的故障验收；缺少双设备并发读写与冲突 UI。
- 所有超过 30 秒的非书架副本待处理行当前保留在本地日志并暂停发送，包括字段、清单、删除和复活。即使只重写字段行的传输时间，也会抬高同一行的清单比较时钟；旧删除重写后也可能抹除较新的复活。须先完成[变更游标与冲突时钟分离方案](../../adr/0004-replica-change-cursor.md)及冲突界面，才能声称长时间离线操作可自动收敛。
- 本地日志使用浏览器本地存储，当前跨窗口保护针对已观察到的旧确认与较新写入；严格的事务级多窗口原子性尚需进一步验证。存储配额/禁用时写入会抛错，产品界面仍需明确展示该错误。
