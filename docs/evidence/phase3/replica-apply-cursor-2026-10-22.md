# Phase 3 首项：本地应用成功后提交副本游标（2026-10-22）

**状态：本项修复已验收；Phase 3 整体仍在开发。** 所有开发、测试和提交都在 Linux 测试服务器进行，未推送 GitHub 或 GHCR。

## 故障与修复

原同步管理器在拉取副本行后立即保存最大 `updated_at_ts`。本地存储的行应用若失败，外层只记录错误；下一次增量请求使用 `updated_at_ts > cursor`，这条未应用的数据因此可能长期被跳过，直到重新执行全量启动拉取。

新的拉取路径保留远端 HLC 观察，但暂缓游标提交。每类行全部成功应用后才提交该类游标；任一行应用失败则保留原游标，下一次 online、focus 或定时增量拉取会重新获取这一类行。书架路径也改为应用成功后提交，批量和单类拉取遵循同一规则。提交时取现有值与新值较大者，避免乱序完成使游标倒退。
