# Phase 3：桌面离线书签恢复与自动重试（2026-10-23）

**范围：服务器隔离 Linux CEF 测试容器、两页合成 PDF、合成账户及回环候选 Web。测试容器访问本机 staging API 的许可已经用户批准。没有开放公网端口，也没有向 GitHub/GHCR 上传。**

## 触发与修复

在旧版测试客户端中，阅读器断开候选 Web 的回环代理后新增书签；本地 `config.json` 保存了书签，但代理恢复后，阅读器未自动重试失败的笔记上传。原先只在笔记数组变化或重新打开书籍时同步。另一个风险是上传失败后仍会拉取；较新的远端时间戳可能推进笔记游标，令有 xpointer 的本地未上传批注失去重试资格。

阅读器现记录失败的笔记上传，并在保持书籍打开时每 15 秒重试；浏览器触发 `online` 时也立即重试。成功上传后停止周期性重试；若两次上传交叠，只有最新尝试的结果可以改变待重试标记，避免旧请求成功清掉新请求的失败。`syncNotes` 在上传失败时返回失败且不拉取，避免推进游标。书签仍由原有本地保存流程持久化，重启后首次打开也会重放。

## 回归与构建

- 新的离线书签用例在修复前失败：期望恢复后的第二次上传，实际只有首次上传。并发顺序用例也先失败：较新请求失败、较旧请求随后成功时，期望第三次重试，实际只有两次。修复后这两项回归和“失败推送不拉取”用例均通过。
- 服务器构建容器中，最终代码的 TypeScript、Biome、Tauri 静态页面构建和未签名 Linux CEF debug 构建均通过；重启最终测试包后打开合成 PDF，侧栏仍显示两页书签。正式签名包未构建。
- 修复前、环境参数正确的完整 Vitest 基线为 1,194 个测试文件通过、4 个跳过；13,909 项通过、16 项跳过。最终修复的完整 Vitest 已通过：1,196 个测试文件通过、4 个跳过；13,912 项通过、16 项跳过，耗时 800.66 秒。日志 `/home/gavin/scholar-phase3-offline-retry-full-test-final.log`。先前一次运行因加入并发顺序修复主动停止，不作为最终结论。

## 真实客户端故障注入

1. 新版客户端从隔离容器本地配置读回旧版离线保存的第 1 页书签；重新打开文献后服务端出现相同 ID 的书签。此项证明重启后的本地保存与重放。
2. 保持新版客户端进程运行，停止**只属于该容器**的候选 Web 回环代理，确认连接失败；翻到第 2 页并用阅读器工具栏新增书签。侧栏显示第 1、2 页，本地 `config.json` 有两条有效书签，服务端此时仅有第 1 页。
3. 恢复代理，未重启客户端；代理只记录 HTTP 方法、路径和响应码，观察到笔记 `POST /api/sync` 返回 200。服务端随后出现第 2 页书签，ID 和本地记录一致，第 1 页仍存在。客户端主进程 PID 在这段测试中保持不变。
4. 界面实测侧栏显示两条书签，第二页书签图标填充；原 staging Web 容器未重启，候选仍只绑定回环端口。

## 边界

这次是真实桌面应用的单设备断网恢复测试；断开的是容器到候选 Web 的本机代理，没有模拟 OS 网络切换、数据库事务中断或两个真实设备同时改同一批注。批注并发、删除/二进制冲突、按需缓存和完整镜像设置仍是 Phase 3 未完成项。正式 staging Web 继续使用原镜像。
